# dsh-recommend sidecar integration

`dsh-recommend` already does the hard part of **global discovery**: a daily crawl of the `dsh-plugin` topic, a transparent four-signal score, a static leaderboard, and a plugin surface. This directory adds the missing **task-conditioned** layer without replacing that ranking.

## Principle

- Keep `dsh-recommend`'s global score and rank. It answers “what is popular/maintained?”.
- Add a **sidecar** label: `dsh-score: memory · E0 unrated`; never a prior `#1`.
- Never overwrite the host score; never use the sidecar to hide a row.
- The sidecar reports E0/unrated by default; the first E2 provisional pilot is labelled, never a quality rank.

## Feed

Generated by:

```sh
node scripts/export-recommend.mjs
```

Output: [`bench-feed.json`](./bench-feed.json)

```json

```

The join key is the GitHub `fullName` already present on every `dsh-recommend` row (`owner/repo`), so no fuzzy matching.

## Site patch sketch

In `dsh-recommend`'s static site renderer:

```js
const feed = await fetch('./data/bench-feed.json').then(r => r.json())
const bench = feed.byFullName[row.fullName]
if (bench) {
  const label = `Bench ${bench.surface} #${bench.rank} · ${bench.score}/${bench.scoreScale} · ${bench.tier}`
  const href = `https://perrylink.github.io/dsh-attention-index/#${bench.surface}`
  rowEl.append(makeBadge(label, href))
}
```

In the plugin's settings/detail card, show the same label plus the prior/bench split:

```text
Community Bench: dev #1 · 39.3/60 · prior
  prior 65.5 · bench — · coverage 0% · confidence 80%
  No paired bench result yet; this is a prior, not an outcome claim.
```

## Sync

- `bench-feed.json` is generated from `dsh-attention-index/data/registry.json`; refresh it in the same job that refreshes the host ranking, or on a slower cadence (e.g. hourly/daily).
- If the feed is missing or stale, render no bench label rather than a guessed one.
- The feed is additive: a repo absent from it simply has no sidecar.

## Why not merge the scores?

A global popularity score and a task-conditioned bench answer different questions. Merging them would let popularity hide a capability miss (or a niche bench winner distort the global ranking). Keeping them side by side preserves both signals and makes the conflict visible.

## What `dsh-recommend` would gain

- A second, **task-aware** reason to click a row.
- A path for new/under-evaluated plugins: `newAndPromising` and `mostNominated` can be surfaced as a “Community nominated” strip.
- A direct link from a global row to the surface leaderboard where the plugin actually competes.

## What this integration will not do

- It will not change `dsh-recommend`'s score, weights, or ranking.
- It will not add paid placement.
- It will not call a plugin “good” without evidence; prior-only rows carry the label.
